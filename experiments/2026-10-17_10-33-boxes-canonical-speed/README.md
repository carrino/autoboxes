# Exact solver canonicalization with byte tables

The solver canonicalizes every visited node by taking the minimum edge mask
over the board's symmetries. Previously it walked every drawn edge separately
for each symmetry. This experiment precomputes each source byte's transformed
mask. Eight lookups and ORs produce each image, and the identity image is the
input mask itself. The same canonical key therefore reaches the same existing
transposition-table entry. Search, move ordering, node accounting, reductions,
and the 50,000-node budget are unchanged.

The lookup payload is 112 KiB per square-board solver (seven nonidentity
transforms × eight bytes × 256 entries × eight bytes), or 48 KiB per rectangular
solver. The usual transposition table remains 16 MiB; `table_bytes()` continues
to report only that table. The lookup tables are initialized once per solver.

## Results

Two alternating rounds on the final source, measured in process CPU seconds:

| Work per pass | Baseline | Byte tables | CPU time saved | Throughput |
|---|---:|---:|---:|---:|
| 4.8 million canonical masks | 0.715s | 0.142s | 80.1% | 5.03× |
| 1,768 solver calls, 48 roots and their children | 75.69s | 59.21s | 21.8% | 1.28× |
| Complete MCTS decisions on 12 roots, including CPU inference | 41.75s | 34.96s | 16.3% | 1.19× |

Every native pass returned the same **609 exact values and 1,159 unknowns**,
with exactly **62,307,428 visited nodes**. Both full MCTS rounds matched every
recorded chosen edge, visit count, selection probability and root proof status.
This improves execution cost while preserving the existing search calculation;
it does not itself improve the model or extend the solver's node budget.

The native baseline passes took 76.93s and 74.46s; candidate passes took 59.29s
and 59.12s. MCTS baseline passes took 41.742s and 41.755s, and candidate passes
34.746s and 35.170s. These are two timing repetitions on one fixed sample,
not independent strength trials. GPU self-play throughput remains to be measured.

Construction/destruction of 1,000 normal 16 MiB solvers averaged 0.673s for
the baseline and 0.672s for byte tables, indistinguishable at this measurement's
noise. With a two-entry table to isolate initialization, the average rose from
1.12 microseconds to 18.68 microseconds per solver. The extra initialization is
paid once per solver, not per node. Additional lookup payload is less than 1%
of the normal TT size.

`data/summary.json` and the per-call CSVs preserve the measured timings and
parity counts; an empty solver `value` in CSV means budget exhaustion.
The MCTS JSONL files retain the complete recorded decision distributions.

## Measurement

`run.py` builds two standalone, single-thread C++ drivers with identical
`g++ -O3 -DNDEBUG -std=c++17` flags. The baseline solver files come from
`ed3fe2c`; the candidate files come from the working checkout. Both consume the
48 frozen arena roots from the preceding search-target audit, at 32, 34, 35,
36, 38 and 40 undrawn edges. These histories were generated by the shared
`play_game` arena; this benchmark only replays masks and solves positions.

Each root gets a fresh 1,048,576-entry table, then the root and each legal child
are probed in ascending edge order with a 50,000-node budget, retaining the
table between those calls. There are 1,768 calls per pass. Construction and
destruction are excluded from solve timings and measured separately. The driver
records returned value (or unknown), exact node count and process CPU time for
every call. Baseline/candidate order alternates across repeated passes.

`mcts.py` selects the first two frozen roots in every band (12 total), recreates
their full board histories, and runs frozen iter0 at 400 simulations,
solver34/50k, leaf batch 16, c_puct 1.5, no noise, temperature zero, terminal
proofs and shaping (lambda 0.5, k 6). Inference is float32 on one CPU thread.
Every root gets a fresh agent/table. Output contains chosen moves, visit
counts, selection distributions, root proof status and process CPU time.

CPU time avoids counting time when other cloud experiments are scheduled.
It does not eliminate shared-cache or CPU-frequency effects, so timing arms
alternate and are repeated. These are cost and exact-trace tests, not an arena
strength measurement or a prediction of RTX3070 throughput.

## Reproduce

From the repository root:

```bash
EXP=experiments/2026-10-17_10-33-boxes-canonical-speed
uv run python "$EXP/run.py" --output work/canonical-speed/native --repeats 2

# This builds both isolated extensions, leaving the installed one untouched.
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 uv run python "$EXP/run_mcts.py" \
  --checkpoint "$REFERENCE" --output work/canonical-speed/mcts --repeats 2
uv run python "$EXP/summarize.py" --native work/canonical-speed/native \
  --mcts work/canonical-speed/mcts --output work/canonical-speed/report

PYTHONPATH=src:work/canonical-speed/mcts/candidate OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  uv run pytest tests/test_boxes_solver_canonical_bytes.py \
    tests/test_boxes_cpp_solver.py tests/test_boxes_solver_bounds.py -q
```

Validation on the final candidate extension: **793 tests passed, 29 skipped**
in 128.77 seconds, excluding only the known upstream GPU-lease test. This
includes all Go tests and the nine added canonicalization cases. Ruff passes
for the new tests and experiment scripts. The tests and measurements use an
isolated extension; the user's running overnight branch is unchanged.

The reference checkpoint SHA256 is
`46c7264c4a0e9c7efa1cfccbb1b511c1c5faa3824fb69a62705d8cbfb1f953f0`.
The canonicalization tests compare to the independent Python lattice
transforms across square, rectangular, 1×N and N×1 shapes, including the
64-edge 1×21 and 21×1 boards. Every valid value of every source byte is tested
inside a deterministic background mask and its complement, covering partial
trailing bytes and the highest bit. Existing solver tests exhaustively compare
all masks through 2×3 to the oracle and exercise budget restarts, collisions,
symmetry, MTD(f), root choices and solver-backed MCTS.
